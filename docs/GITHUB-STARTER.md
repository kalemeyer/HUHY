# GitHub starter guide

You do not need to be a coder or know Git commands to help with HUHY. Research,
writing, design, testing, subject knowledge, and maintenance are all useful.

> **GitHub is public.** Use publicly released, non-sensitive information only.
> Never post PII, PHI, CUI, credentials, internal screenshots, readiness or
> operational information, or material from a restricted system.

The website version of this guide is available at
[huhyproject.org/github-guide](https://huhyproject.org/github-guide).

## Help without writing code

1. [Create a free personal GitHub account](https://github.com/signup). You do
   not need a government email, CAC, or special access.
2. Choose an approved HUHY project and open its linked GitHub issue.
3. Read the public problem, sources, risk, and requested roles.
4. Leave a comment naming the role you can fill and one small first task.
5. Coordinate in the issue so decisions and ownership stay visible.

You can copy this introduction:

```text
I'd like to help with: [role or task]

I can contribute: [brief public description]

A good first task for me could be: [small starting point]

Availability: [one-time help or ongoing]

I confirm I will use public, non-sensitive information only.
```

## Change code or documentation

1. Comment on the project issue before starting.
2. Fork the repository. A fork is your personal copy.
3. Make one focused change. GitHub's browser editor is sufficient for many
   documentation and small code changes; a command line is optional.
4. Open a pull request, link the project issue, and explain what you tested.
5. Respond to review. Questions and requested changes are a normal part of the
   process.

Follow the contribution and sign-off requirements in
[`CONTRIBUTING.md`](../CONTRIBUTING.md).

## Volunteer as a maintainer

1. Volunteer on the project issue and name the area you can own.
2. State realistic availability and whether backup is needed.
3. Review the project's risk, source, release, and support expectations.
4. The project lead or HUHY Steward confirms and records the ownership and
   review cadence.

Maintenance is an ongoing responsibility for review, releases, upkeep, and
handoff—not simply a title.

## Common GitHub terms

- **Repository:** the project's code, documents, history, and rules.
- **Issue:** a public discussion for a problem, task, question, or decision.
- **Fork:** your personal copy of a repository.
- **Branch:** a separate line of work.
- **Commit:** a saved set of changes with a short explanation.
- **Pull request:** a request for maintainers to review and possibly merge a
  change.
- **Maintainer:** a person responsible for a defined area of project ownership.

If you are unsure where to start, ask in
[GitHub Discussions](https://github.com/kalemeyer/HUHY/discussions) without
including sensitive or personal information.
