# Contributing

Contribute only material you are authorized to share publicly. Do not use
government credentials, restricted systems, internal records, sensitive
screenshots, or nonpublic data to develop or test HUHY work.

Before starting:

- Confirm the issue was created through the HUHY safety-reviewed workflow.
- Check the governing public sources and their dates.
- State whether the contribution is private-capacity or authorized official-duty work.
- Confirm ownership and licensing for every dependency, asset, and source.
- Keep test fixtures synthetic and non-identifying.
- Read the project&apos;s risk, source-review, and maintenance requirements.

Pull requests should identify the HUHY issue, explain the user-facing change,
list public sources, describe validation, and name any maintenance impact.

Existing third-party tools remain with their owners. Link or contribute upstream
when invited; do not copy or rebrand another project.

## How to contribute

1. Use [huhyproject.org](https://huhyproject.org) to suggest a new problem or recommend a tool.
2. For an approved project, comment on its GitHub issue with the specific role you can fill.
3. Fork the repository and open a focused pull request linked to the approved issue.
4. Run the checks documented by the affected app and report the actual results.
5. Stay available for review or state clearly when someone else should take over maintenance.

Public defects in HUHY itself may use the bug-report issue form. Never use a
public issue for sensitive information or a government-system vulnerability.

## Developer Certificate of Origin

HUHY uses the [Developer Certificate of Origin 1.1](https://developercertificate.org/).
Sign off each commit with `git commit -s` to certify that you have the right to
submit the contribution under this repository&apos;s license. AI tools may assist,
but the human contributor remains responsible for the contribution and its
public-release, ownership, and validation claims.
